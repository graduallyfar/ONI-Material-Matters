# V0.2.0 文本信息检查

2026-10-15。用户要求整个新增文本贴合游戏原内容。本轮已核对全部80条本地化文本，覆盖强制按钮、模式、运行状态、风险和损坏、配方详情、温度效果、硬度、加热滑条与自动化端口。

## 1. 原版依据与信息分工

基准来自本机游戏 `OxygenNotIncluded_Data/StreamingAssets/strings/strings_preinstalled_zh_klei.po`：建筑按钮使用“启用／禁用”，制作状态为“等待材料”“无制作队列”“操作任务”，过热状态为“损坏：过热”。原版温度效果带 `HEAT` 百科链接，温度传感器输出使用 `logic_on` / `logic_off` 样式突出红绿信号。

同时核对本地 `BuildingDef.Desc`、`Building.EffectDescriptors`、`Overheatable.GetDescriptors` 和 `ComplexFabricator.AdditionalEffectsForRecipe` 的显示分工：用途留在原版建筑描述；工作温度在效果区；配方最佳温度在配方详情；当前运行与损坏在状态区。过热效果保留原版标签、百科链接和属性明细，不另造一条替换它。

## 2. 修改与显示修正

- 短标题先说明状态，悬停再解释条件与数值。中文默认值、中文翻译和代码备用文本同步。
- 玩家文字使用“生命值”“建造材料”“启用／禁用”，移除“HP”“重判”“许可”“锁定批次”“注热”等开发表述。暂停保留进度等说明换成直接的玩家语言。
- 补齐配方详情悬停：最佳温度对应100%温度效率，实际速度还受复制人的操作能力影响。
- 强制运行悬停说明解除的是温区限制，材料、电力、操作和自动化仍有效；粉碎机独立说明没有内置加热。
- 控制模式的最佳温区完全不可达时，到达材料上限停热即显示“生产暂停：温区受限”，不会误写成等待复制人操作。
- 强制运行不再显示普通预热／补热目标，避免把不封顶的持续加热写成会在某个温度停止。
- 损坏标题采用“损坏：原因”。只有支持内置加热且已有过热损坏的建筑，才追加“内置加热已停止，完全修复后才能恢复”；粉碎机不会出现该句。
- 输出信号说明只报告当前配方温度，不代表正在生产。生产控制红信号仅暂停生产，有内置加热的建筑仍可按需要预热或补热。

本版仍为0.2.0。没有修改配方、数值、生产条件或存档数据；本轮完成此前未提交的原版效果区排布调整。
