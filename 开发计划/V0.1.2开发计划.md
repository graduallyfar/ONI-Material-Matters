# V0.1.2 开发计划

日期：2026-10-14。状态：**已交付代码，游戏内验收未运行。** 三处版本号为 `0.1.2`；Release 构建 0 警告、0 错误，判断层／接入替身源码级测试 **931 项断言全通过**（本轮由 812 项增加而来）。已实现的规则见 §8，§7 列出本轮采用的暂定值及其性质。**尚未部署、未启动游戏。**

本版将建筑工作温区与配方最佳温区拆开，合并建筑最高工作温度与材料过热阈值，并明确加热目标受限时的信息卡显示。依据本次用户确认，取代此前“配方拥有四个边界、过热系数 0.85”的设计。旧版本开发计划保留为实际实现记录，不追改成已实现新规则。

## 1. 已确认范围与保留机制

### 1.1 已确认规则

| 对象 | 规则 |
| --- | --- |
| 温度对象 | 仍为建筑本体，不增加独立工艺温度 |
| 建筑最低工作温度 L | 由建筑类型决定，切换配方、换建造材料不改变；具体建筑数值待定 |
| 建筑最高工作温度 U | 等于过热阈值，由主建造材料决定：`U(K) = 0.75 × 主材料熔点(K)` |
| 配方最佳温区 [B₁, B₂] | 只由配方决定，不随建材变化；要求 `L ≤ B₁ < B₂` |
| 配方范围限制 | 不设计最佳下限低于建筑下限的配方，删除此前低侧部分重合、最佳区整体低于建筑下限两类玩法情形 |
| 普通运行 | 默认模式满足建筑工作范围；控制模式还需满足配方最佳温区；超过 U 时两种模式都停产并停止内置加热 |
| 强制运行 | 覆盖温度停机与加热目标限制，保留过热损伤、材料相变、生命值耗尽停机及其他非温度条件 |
| 预热优先级 | 建筑工作温区优先于配方相关加热目标；不能为追求原目标而越过 U |

摄氏显示为 `U(℃) = 0.75 × 熔点(K) − 273.15`，不直接将摄氏熔点乘 0.75。0.75 是本次确认的新系数，**已替换源码中的 0.85**。

### 1.2 保留内容

- 保留预热、补热与强制持续加热流程；20–4000 W 共用滑条、1 W 精度、每栋建筑独立保存、默认 1200 W、生产用电另计及暂定注热倍率均不改。
- 保留输出接线选择默认／控制模式、强制独立开关、输入红信号只禁止生产而不禁止配方准备和加热。
- 保留有序订单、先锁定批次、缺料调度、已投料视为原料齐备、暂停保留进度；不可达配方不自动取消或跳单。
- 保留硬度磨损、损坏原因、维修流程与强制过热双原因显示规则，不增加额外扣血。
- 保留无有效批次不加热，断电、禁用、损坏时不注热；不新增主动制冷或无加热建筑的内置加热能力。
- 本版计划不顺带接入其余 13 栋工业候选或扩大实际生效名单。

## 2. 温度与加热判断

### 2.1 数据归属与合法性

建筑配置提供 L，建筑实例主材料提供 U，配方配置只提供 B₁、B₂。切配方只更新最佳区及相关目标，不更新建筑范围；不能将材料上限裁剪进配方最佳温区后再保存为配方数据。

有效普通工作范围要求 `L < U`；配方要求 `L ≤ B₁ < B₂`。不再要求 `B₂ ≤ U`，也不再把 `B₁ > U` 判成配方错误：后者是建材无法覆盖最佳区的正常情况。`B₁ < L` 应在设计与配置校验阶段纠正，不作为正常玩法分支；异常配置运行时的安全回退方案见 §7。

### 2.2 生产许可

- 默认模式的温度范围为 `[L, U]`，仍保留首次启动和恢复回差判断。
- 控制模式的温度范围为 `[B₁, min(B₂, U)]`，并保留启动和恢复判断；`B₁ > U` 时无可用最佳区，不能生产。
- `T = U` 不因“超过上限”规则停机；`T > U` 时普通运行高温保护。实际模拟的浮点误差、生产自热及伤害触发顺序必须验收，不能承诺卡在上限绝无伤害。
- 高温保护停止生产与内置加热，不免除环境造成的过热损伤，不自动降温。
- 强制模式只覆盖温度限制，非温度条件仍独立生效。

### 2.3 原目标与实际目标

保留现有启动线计算方式（比例 0.1），仅将最低温度来源改为建筑配置，并对实际目标应用建筑上限：

```text
默认原启动目标 S₀ = L + 0.1 × (B₁ − L)
控制原启动目标 S₁ = B₁ + 0.1 × (B₂ − B₁)
普通实际启动目标 S = min(对应原启动目标, U)
```

由于 `B₁ ≥ L`，合法配置不会出现预热目标低于建筑下限的情形，不再需要低侧玩法分支。即使默认原启动目标超过 U，也必须封顶。

加热与生产门控必须使用同一个实际启动目标，避免“加热停在 U，生产仍等待原先更高启动线”。控制模式达到 S 后仍须满足最佳区，不可因封顶而绕过 `B₁`。

补热沿用原流程与功率，停止目标不得高于 U，普通注热末步按实际目标剩余热量封顶。不能在范围被截窄后继续沿用越出可用区间的启动／恢复线；窄交集的补热与高温恢复回差具体取法待 §7 定案，不擅自引入新的百分比。

### 2.4 无交集与强制运行

`B₁ > U` 时，控制模式可以按既有许可预热到 U，但到达后停止加热并保持生产暂停，提示最佳区不可达。后续失热时依照最终确认的加热回差恢复判断，不新增无限贴边保温或自动跳单规则。

默认模式仍可在建筑范围内按低温效率生产。切换模式不取消批次。强制开启后可越过 U 继续加热和生产，但不改写配方最佳区；关闭后立即按当前基础模式及实际温度重判。

## 3. 四种主要情况及信息卡显示方案

以下为**本版已实装的状态文案与机制**。示例统一使用建筑范围 **100–600 ℃**，仅解释边界，不作为金属精炼器或其他建筑的数值定案。

表中默认／控制启动目标分别按 §2.3 计算。所有“生产中”均以实际生产进度在推进为前提；温度允许但等待操作时，沿用原版操作提示，不能提前显示生产。

| 编号与情况 | 配方最佳区 | 默认实际启动目标 | 控制原目标 → 实际目标 | 控制模式状态栏变化 | 独立温区提示及悬停说明 |
| --- | --- | --- | --- | --- | --- |
| A 最佳区完全可用，B₂ ≤ U | 200–400 ℃ | 110 ℃ | 220 → 220 ℃ | 实际注热时「预热中」；开工后「生产中」；边生产边补热时「生产中 · 补热中」 | 不额外显示材料限制提示 |
| B 最佳区部分可用，启动目标可达 | 500–700 ℃ | 140 ℃ | 520 → 520 ℃ | 「预热中」→「生产中」，实际补热时追加「补热中」 | 「最佳温区受限」；配方区间 500–700 ℃，本建筑普通控制可用区间 500–600 ℃ |
| C 最佳区部分可用，启动目标被封顶 | 590–790 ℃ | 149 ℃ | 610 → 600 ℃ | 「预热中」→达到 600 ℃后满足启动温度条件；实际开工显示「生产中」 | 「最佳温区受限」；说明原目标 610 ℃、实际目标 600 ℃，控制可用区间 590–600 ℃ |
| D 最佳区整体高于建筑上限，B₁ > U | 700–900 ℃ | 160 ℃ | 720 → 600 ℃ | 「预热中」→达到 600 ℃停止加热，显示「温度受限 · 生产暂停」 | 「最佳温区不可达」；建筑上限 600 ℃低于配方最佳下限 700 ℃，普通控制模式无可用温区 |

默认模式下，A–D 均先按各自默认目标预热，开工后低于 B₁ 时显示「低温低效生产」；进入最佳区显示「生产中」；高于 B₂ 但未超过 U 时显示「高温低效生产」。B／C 的「最佳温区受限」、D 的「最佳温区不可达」仍可作为独立提示，但悬停必须说明限制针对普通控制生产，不得把默认模式低效生产写成停产。

删除上一轮示例中的 `50–150 ℃`、`20–80 ℃` 两行：它们都违反 `B₁ ≥ L`。不是删除低温低效生产，也不是禁止实际建筑温度低于 L。

### 3.1 相等边界

- `B₁ = L` 合法，不属于已删除情况；默认原启动目标就是 L。
- `B₂ = U` 归 A：最佳区完整可用，不显示「最佳温区受限」。
- `B₁ = U` 时控制交集只有一个温度点：预热目标封顶 U，显示「最佳温区受限」，悬停注明仅在上限点相交；不得误报完全无交集。该点与恢复回差如何兼容仍待 §7，不把它当作稳定生产承诺。

## 4. 信息卡状态栏的统一显示

### 4.1 显示分工

1. **模式项**始终显示「运行模式：默认模式／控制模式」，沿用输出接线选择；强制开关开启时独立显示「强制运行已开启」，即使断电或损坏也不能据此声称正在强制生产。
2. **运行项**只描述实际行为或温度暂停原因，见下表。原版已有的等待材料、操作任务、手动禁用、断电与损坏提示优先复用，避免添加同义条目。
3. **温区限制提示**根据当前锁定配方及建材显示「最佳温区受限／最佳温区不可达」，不能冒充损坏。无锁定批次时不沿用上一配方的提示；查看其他配方只改变详情，不改变当前运行状态。实装为独立状态项 `ZONELIMIT`（中性通知级别），悬停给出完整温区口径。
4. **过热风险与实际损坏**独立显示。温度越过 U 先显示「超过过热阈值」；只有实际记录到伤害才显示损坏原因。机械与过热原因并存时继续分别保留。

### 4.2 运行与风险状态表

| 实际情况 | 运行状态或沿用的原版提示 | 独立风险／补充说明 |
| --- | --- | --- |
| 低于 L，未强制，实际在注热 | 预热中 | 悬停给出当前温度、L 和实际启动目标 |
| 需要预热但当前没有注热、也无更具体的断电等原因 | 等待升温 | 不假称正在预热；无内置加热对象也不能借本版获得加热能力 |
| 温度已满足，尚未实际开工 | 沿用原版操作／其他等待提示 | 不显示「生产中」；只有所有温度条件满足才允许创建操作任务 |
| 默认模式低温低效生产 | 低温低效生产 | 低效按配方温度关系判断，具体效率公式待定 |
| 最佳区内实际生产 | 生产中 | 实际补热时显示「生产中 · 补热中」 |
| 默认模式高于最佳上限、仍在建筑工作区内生产 | 高温低效生产 | 不称为过热，除非真实超过 U |

| 普通模式 T > U | 高温保护 · 等待降温 | 同时显示「超过过热阈值」；已受伤时保留实际损坏原因；生产与加热均停 |
| 已回到 U 以下但尚未满足恢复回差 | 等待降温 | 不再显示当前超温风险；已记录的损坏原因仍保留 |
| 控制最佳区不可达，仍在实际预热 | 预热中 | 独立显示「最佳温区不可达」，说明到上限后仍无法控制生产 |
| 控制最佳区不可达，到达受限目标且无注热 | 温度受限 · 生产暂停 | 独立显示「最佳温区不可达」；不能写「等待操作」或仍写「预热中」 |
| 自动化禁止生产，但实际在预热／补热 | 生产已被自动化暂停 · 预热中／补热中 | 温区限制提示仍可并存；红信号不停止加热 |
| 强制开启，低于最佳下限且实际生产、注热 | 低温低效生产 · 持续加热 | 独立强制开关状态；超过 U 时另显过热风险 |
| 强制开启，在最佳区且实际生产、注热 | 生产中 · 持续加热 | 即使已经超过 U，也不能因材料过热而改称「高温低效」；另显过热风险 |
| 强制开启，高于最佳上限且实际生产、注热 | 高温低效生产 · 持续加热 | 低效曲线与过热伤害分别判断 |

| 强制开启但等待操作，实际持续注热 | 沿用原版操作提示；运行项显示「持续加热」 | 不显示生产中 |
| 断电／手动禁用／损坏停机 | 沿用对应原版提示 | 不附预热、补热、持续加热或生产中；保留模式及真实损坏信息 |
| 无批次、无订单或缺料 | 沿用原版安排／缺料提示 | 停止加热，清除旧配方限制提示；独立过热与损坏信息仍按实况显示 |

### 4.3 组合与优先级约束

- 先判断损坏、禁用、断电、无批次等真实阻断，不能由温度允许覆盖它们。温度故障和实际损坏可继续通过独立提示解释。
- 有批次、普通模式超出建筑上限时，运行项优先显示高温保护；不能写成仅由自动化导致暂停。若自动化也禁止生产，保留其原版提示或在悬停补充。
- 实际加热状态取自已注入热量，生产状态取自真实进度推进。仅有加热需求或生产许可不足以显示“正在”。
- 达到 U 不等于已经过热受伤；不新增提前停机安全余量。普通模式停机也不免除环境升温造成的伤害。
- 强制状态、温度效率、材料过热风险彼此独立。关闭强制后超温立即停产停热，保留批次和损坏原因。
- 悬停显示本体温度、建筑范围、配方最佳区、原／实际加热目标（仅受限时需要两者）、限制原因；按玩家温度单位格式化，所有新增文案使用本地化键。
- 配方详情显示配方最佳区；建筑工作范围取当前建筑与主材料，不能继续把旧 300–800 ℃当作炼铝配方固有范围。沿用原版配方名称与安排界面，不恢复额外订单侧屏。

## 7. 本轮采用的暂定值（原「尚待确定的内容」）

§7 的六项未定内容，本轮按用户指示「先实现已确认规则，未定项给暂定值并逐条标注」处理如下。**以下除第 1 项外都是暂定值，不是最终平衡结论**，改动集中记录在 `Core/Balance.cs` 与本节。

1. **各建筑最低工作温度数值。** 金属精炼器取 **80 ℃**（用户 2026-10-14 给定，已确认）。只登记这一栋；其余建筑仍未定，未登记的建筑不启用本 Mod 温控。注意这不等于“所有精炼配方共用 80 ℃”：未配置最佳温区的配方仍按原版行为运行。
2. **效率曲线及强制越界效率。** 本轮采用：最佳区内恒 100%；`L ≤ T < B₁` 为 `0.30 ^ ((B₁ − T) / (B₁ − L))`；`B₂ < T ≤ U` 为 `0.80 ^ ((T − B₂) / (U − B₂))`；越界保持对应侧底值 0.30／0.80。底值沿用旧实现，**段宽改为建筑范围**，因此低熔点建材不会改变最佳区效率。强制越界仍用同一曲线，没有单独的强制效率档；是否让同一配方同温度的效率完全不受建材影响已经是本版结果（建材只通过 U 改变高温段终点）。
3. **窄交集、单点交集和无交集后的回差。** 本轮暂定：回差仍取默认 15 K／控制 10 K，但**最多取「实际启动目标 − 生产下限」**，因此窄交集不会出现倒置或达不到的恢复线，单点交集回差为 0；补热启动线不低于 B₁。未新增安全余量、保温模式或百分比。
4. **建筑上限不高于建筑下限时的处理。** 本轮采用：**退回原版行为**并记录一条可定位日志（`zone|empty-range`），不引入无限上限、也不新增玩法分支。限制提示与强制运行在该组合下仍由原版机制决定，本版不做额外承诺。
5. **未配置配方与异常数据兼容。** 本轮口径：**建筑下限与材料上限只对已登记最佳温区的配方生效**；同栋建筑未配置的配方完全按原版运行（只保留建筑级过热阈值规则）。`B₁ < L` 记录日志并把下限抬到 L 继续运行；`B₁ ≥ B₂`、非有限值、无效熔点、`U ≤ L` 都退化为未配置并记录日志。**不扩大生效名单。**
6. **本次新增状态文案。** §3–4 的方案已实装为本地化键，文字可按用户反馈调整，不改动已确认机制。

### 7.1 另需用户确认或后续处理

- 补热与高温恢复的回差取法（第 3 项）是本轮为了让窄交集可运行而定的，**不是平衡定案**。
- 除金属精炼器外的建筑下限（第 1 项）与其余工业配方的温区仍未定案，接入前需先补这些数值。
- 第 2 项的底值 0.30／0.80 只沿用旧实现，段宽变化后低温段明显更平缓（80→450 ℃），实际手感需要游戏内确认。
