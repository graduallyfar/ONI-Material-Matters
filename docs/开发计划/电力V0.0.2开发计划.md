## 1. 结算边界

- 保留原版`Sim200msLast`的0.2秒门槛、消费者排序、连接状态判断、统计写回与过载检查。仅转接其中8处取电／充电调用；签名和调用数量全部匹配才应用补丁。
- 发电机与变压器输出沿用原接收类别的`ApplyDeltaJoules`／`ConsumeEnergy`扣电。变压器重载会同步内部电池，不再手动重复扣款。普通电池放电使用`ConsumeEnergy`，充电使用`AddEnergy`。
- 电池每笔传输分角色：放电是供电端，充电是接收端。同轮分别记账，不按净储能变化计费；普通电池充电保留原版源端至少1J门槛，不新增普通电池之间自动充电，不从自己或同建筑的另一组件给自己充电。
- 电桥、同格、端点和混合线材仍按[[3. 电力系统设计]]。不改原版导线容量、过载伤害、装饰值和建筑材料范围，不新增热量或环境发热。
- 拓扑、路径与材料系数只随电网／设备重建刷新；模拟轮仅更新预算与账本。清理、重建和换世界使旧账本失效，原版储能字段继续负责存档。
- 虚拟／半虚拟连接、无物理路径、未知材料或超范围系数，整网保留原版结算；在扣电前检查，信息卡与日志给出原因，不静默按零损耗处理。

## 2. 已确认采用的供电规则

1. 对每个接收端，把当前可放电的发电机、变压器输出和普通电池统一按最短线路排序。充电中的电池是接收端，不在该笔充电中当作自己的电源。
2. 等距按接电格编号，再按对象实例ID处理；实例ID仅保证当前会话稳定，不作为跨存档身份。
3. 近源不足时先供给预算内部分，再由后续源补足。同源到同接收端按本轮累计传输功率计算边际损耗，不随内部调用切分重置负载。
4. 用有界二分（最多64次）求满足`交付J + 损耗J <= 源可用J`的交付量，报价不修改能量。转为游戏float时交付向下取值、扣款向上取值并限于源预算，舍入差并入实际损耗显示。
5. 普通设备最终欠供时保留原版`Unpowered`结果，已经支付的部分不退回，不新增半速生产。电池和变压器输入可部分充电。
6. 设备供电后，变压器输入先充电（候选包括电池），普通电池随后只从发电机／变压器输出充电。原版后续重复充电调用不会重新扣款。相较原版分类别顺序，电池给变压器的补充可能提前到变压器首次充电阶段。

用户先强调区分电池输入与输出角色，随后明确确认「采用这些测试口径，完成电力0.0.2」。上述规则已采用，首轮数值不等于最终平衡。

## 4. 信息卡与记账

- 保留「电线数量」，仍是选中独立电网的已建成电线格数。
- 新增最近一轮「线路损耗」「实际输送」；输送包含设备、电池充电和变压器输入，不能和原版`wattsUsed`直接相加当作源支出。
- 损耗来自源端实际扣款减接收端实际交付，单列能源报告「线路损耗」。充电交付本身不重复报为最终消耗；消费者交付沿用原版耗能报告。
- 不支持时显示「原版结算」并说明原因；尚无账本显示「等待结算」。原版提交信息卡前写行，保留原版其他行。
