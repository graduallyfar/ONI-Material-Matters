## 2. 用电与注热

设滑条为 P W，原版金属精炼器生产功率为 1200 W。

| 当前活动 | 加热需求 | 生产需求 | 整机需求 |
| --- | --- | --- | --- |
| 单独预热 | P | 0 | P |
| 仅生产 | 0 | 1200 | 1200 |
| 生产并补热 | P | 1200 | 1200 + P |
| 强制生产并持续加热 | P | 1200 | 1200 + P |
| 自动化红或等待操作工，仍需加热 | P | 0 | P |
| 断电 | 保留应有需求 | 保留应有需求 | 实际消费为 0，不注热 |
| 无有效批次、手动禁用、损坏停机 | 0 | 0 | 0 |

4000 W 是加热上限；同时生产时总需求可达 5200 W。注热仍沿用暂定倍率 1000，P W 对应 P kW，Q = P × dt kJ，不是最终物理换算或热平衡结论。普通预热／补热按目标剩余热量封顶，强制持续加热不封顶。

## 3. 实现与原版依据

- 本机实际安装 `Assembly-CSharp.dll` 已核对 `ISingleSliderControl`、`SingleSliderSideScreen`、`SliderSet` 和 `ComplexFabricatorSideScreen`。原版 `SliderSet.SetTarget` 设置范围、单位、精度，并调用目标设置方法；原版滑条传入的是实际功率数值，不是百分比。
- `Game/MaterialOverhaulFab.PowerControl.cs` 实现原版接口，以 `[Serialize] configuredHeatingWatts` 保存实例值。`RestoreState` 调用功率校验：合法值保留，越界钳制，0／NaN／无穷回默认值。不在 UI 回调里推进模拟。
- 非加热建筑返回 min == max，复用原版 `SingleSliderSideScreen.IsValidForTarget` 隐藏控件。
- `Game/Patches/HeatingPowerSideScreenPatch.cs` 只将目标为本 Mod 加热建筑的单滑条侧屏排序设为 -1。原版配方侧屏继承基类排序 0，`DetailsScreen` 按排序从大到小放置，因此滑条在配方卡下方；其他原版滑条不改排序。基类补丁和原版私有 target 字段均与本机 DLL 签名核对。
- `Heating/HeatingPower.cs` 统一设置校验和转换，删除可独立改写的全局电／热功率字段。`PowerDemandContext.ConfiguredHeatingWatts` 将建筑设置带入耗电判断；实际 `InjectHeat` 使用本步 `UsedHeatingWatts` 换算，保证注热与消费同源。
- `Core/Balance.cs` 集中范围和默认值，`ModStrings.cs` 与 `strings/zh.po` 添加本地化。版本更新 `MaterialOverhaul.csproj`、`Core/ModInfo.cs` 和 `mod/mod_info.yaml`；启动日志注明共用滑条。
- 同步总体设计、[[2. 建筑系统设计]] 与 AGENTS 摘要；历史版本开发记录保留其当时数值，不视为最新规则。
