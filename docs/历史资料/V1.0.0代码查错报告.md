## 结论

没有找到会导致加载失败、崩溃或坏档的问题。找到 2 个中等问题（效果不生效或原版加成丢失）、1 个中低问题（保持回差失效）和 3 个低问题。都集中在房间系统，工业和电力部分没有发现新问题。

## 已核对、未发现问题

- **补丁能否装上**：所有使用原方法参数名的补丁（`dt`、`recipe`、`effect`、`slot`、`idx`/`geyser`、`craft_status`、`attemptTravelAmount`、`index`、`count`、`def`、`smi`、`targetPanel` 等）与当前程序集的参数名一致；`___elapsedTime`、`___generators`、`___consumers`、`___bridges` 字段存在；所有 `FieldRefAccess`／`AccessTools.Method` 反射的字段和方法存在且没有重载歧义。因此不会出现「Harmony 补丁装配失败」导致整个 Mod 不加载。
- **三系统共用目标**：`Workable.GetEfficiencyMultiplier`（房间先乘、工业后记录，磨损计时正确）、`ComplexFabricator.ComputeWorkProgress`、`ElementConverter.GetSpeedMultiplier`（乘法叠加，工业反解真实生产秒数时已包含房间倍率，磨损不多算）、`BuildingLoader.CreateBuildingComplete`、`LegacyModMain.ConfigElements`（过热与装饰度改不同属性）、`Db.Initialize`、`Game.OnCleanUp`，顺序都安全。
- **电力结算**：IL 替换的 8 个调用点、变压器 `ApplyDeltaJoules`/`ConsumeEnergy` 重载与原版一致；`UtilityNetworkManager` 私有字段类型匹配。
- **存档**：只有工业组件有存档字段，订单数组读档逻辑兼容旧档；地质调谐的额外修正不会随存档叠加（原版 `Geyser.modifications` 不序列化）；房间、电力没有存档数据。

## 问题（按严重程度）

### 1. 【中】诊疗床恢复效果在治疗状态切换时被整体清除，护理员加成实际不生效

- 位置：`MaterialOverhaul/Game/Patches/RoomPatches.cs:409-428`（`StopEffect` 后置调用 `RoomRecoveryEffect.RemoveAll`），配合 `RoomPatches.cs:436-478`。
- 原因：原版 `Clinic.ClinicSM` 在 `healing.undoctored` 退出时就会调用 `StopEffect`（原版源码约 232505 行），这只是「未诊疗 → 已诊疗」的内部切换，患者仍躺在床上。但补丁在任何一次 `StopEffect` 都移除全部三种恢复效果。
  - 护理员：医生完成诊疗时补丁先加上护理员加成，随后原版完成任务、切换到 `newlyDoctored`，退出 `undoctored` 时的 `StopEffect` 把它立刻删掉，之后没有地方再加回来。所以护理员 +25% 永远不会留下。
  - 医院／医疗中心：患者带着「已诊疗」效果重新上床时，原版先进 `undoctored` 再直接跳到 `doctored`，跳转时恢复效果被删掉，而 `doctored` 进入时不调用 `StartEffect`，整段已诊疗期间都没有房间恢复加成。
- 游戏内复现：建医院，让带「护理员」（BedsideManner）特质的医生给病床上的患者诊疗，完成后查看患者效果列表，没有护理员加成。另外让已被诊疗过的患者离床吃饭后回床，医院恢复效果消失。
- 建议修法：只在患者真正离开治疗（`Clinic` 工作停止或离开 `operational.healing`）时移除，不在 `StopEffect` 时移除。

### 2. 【中】顶替实验室的新房间丢掉原版实验室 +10% 科研工作效率；顶替娱乐室的新房间不再有闲聊格

- 位置：本 Mod 只补了 `RoomTracker.IsInCorrectRoom`／`OnUpdateRoom`（`RoomPatches.cs:296-351`）。原版还有两处直接比较房间类型：
  - `Workable.OnUpdateRoom`（原版约 157295 行）：`room.roomType == RoomTypes.Laboratory` 才给科研建筑的工作 +10%。任务控制室、地热调谐实验室、数据机房顶替实验室后，研究站、望远镜、指挥站、调谐仪都拿不到这 +10%。任务控制室和调谐实验室虽有本 Mod 的 +20%，但实际只剩 +20%，不是叠加后的数值；数据机房里的研究站直接少了 10%。
  - `MingleCellTracker.Sim1000ms`（原版约 139150 行）：只在 `RecRoom` 里生成闲聊格。舞厅、街机厅、海滩、展览馆、风洞、水疗、茶室顶替娱乐室后，复制人休息时间不会在这些房间里闲聊。
- 游戏内复现：在数据机房里放研究站，让复制人研究，状态栏没有「实验室工作效率加成」；同样的布局如果只满足原版实验室，就有。
- 需要你决定：顶替房间是否应保留原版实验室／娱乐室的这两项效果。我推荐保留，因为顶替的本意是「升级版」，而且 `RoomTracker` 已经按「仍算实验室」处理。

### 3. 【中低】保持回差在房间重建时失效

- 位置：`MaterialOverhaul/Game/RoomRegistration.cs:369-372`（`PreviousRoomId` 取 `room.roomType`）。
- 原因：原版 `RoomProber.CreateRoom` 每次重建都 `new Room`（原版约 354271 行），新对象的 `roomType` 为空，所以只有环境监视器在旧 `Room` 上重判时回差才生效。房间里建造或拆除任何建筑、改墙等拓扑变化都会重建房间，此时按进入线重新判定。
- 游戏内复现：让私人卧室的平均装饰度落在「进入线」和「保持线」之间（房间已成立、继续保持），然后在房间里建一盏灯或拆一个装饰品，房间立刻降级。对应测试清单 C21。
- 建议修法：在 `RoomProber.UpdateRoom`／`ClearRoom` 时按 cavity 记住上一类型，`CreateRoom` 判定时使用。

### 4. 【低】偏好特质效果在房间里完成任何工作都会发放

- 位置：`RoomPatches.cs:177`。`Workable.CompleteWork` 后置对本 Mod 房间里的所有工作都调用 `RoomTraitEffects.TryApply`，包括扫地、修理、搬运、医生诊疗；普通效果走 `TriggerRoomEffects` 有主设施过滤，特质分支没有。
- 影响小：同一个复制人进入房间时已经会拿到特质效果（`CavityInfo.OnEnter` 补丁），这里主要是刷新持续时间。
- 复现：带对应偏好特质的复制人在舞厅里扫地，完成后效果计时被刷新。

### 5. 【低】房间环境监视器的静态缓存不随存档清理

- 位置：`MaterialOverhaul/Game/RoomEnvironmentMonitor.cs:33`（`Stamps`）、`RoomSnapshotCache.cs`。`Game.OnCleanUp` 补丁（`RoomAdvancedPatches.cs:16-24`）只清了航天和调谐状态。
- 影响：回主菜单再读另一个档时，旧档的 `Room` 对象留在字典里不释放，直到被清理逻辑碰到。不影响判定结果，只是内存占用。

### 6. 【低】星际货运站冷却加速的状态判断比注释宽

- 位置：`RoomAdvancedPatches.cs:609`。代码检查的是 `on.cooldown`（含 `pre`、`pst` 动画阶段），注释写的是只在 `on.cooldown.loop` 加速。差别只有动画那一小段时间的额外递减，对数值影响很小。
