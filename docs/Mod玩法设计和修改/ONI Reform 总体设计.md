# ONI Reform 总体设计

本 Mod 不改材料数量，也不是单纯重平衡现有数值，而是改变**材料属性如何参与建筑、环境和系统运算**，让原本差异不明显的材料选择真正变成工程选择。

本文是总体设计，只讲目标、原则、各系统的设计意图、路线与交付状态。规则边界与全部数值在 4 份分设计里，逐版本的实现、回归与验收记录在 `docs/开发计划/` 的版本开发计划里。

# 1. Mod 核心目标

> 通过改变「材料属性如何参与建筑、环境和系统运算」的方式，让原本差异不明显的材料选择，真正变成工程选择。

## 1.1 核心设计原则

1. 大多数材料仍然「能用」，避免不同小行星的资源差异直接卡死玩法。
2. 不合适的材料不一定禁止使用，但会带来效率、维护、能耗或环境上的代价。
3. 尽量复用原版已有的属性和系统，只增加少量必要的新规则。
4. 材料不是升级树，而是 trade-off，不存在一种材料在所有场景里都最优。
5. 不增加新的纵向玩法，重点增加原版系统之间的横向联系和材料选择深度。
6. 所有选择都不是必须的，但确实存在最合适的。

## 1.2 边界与不做的事

- 不扩展与材料参与运算无关的新玩法，不做统一材料升级树。
- 不按共享组件或机制关联自动扩大建筑、配方与系统范围；接入以用户确认的明确名单为准。
- 不擅自展开数值平衡；已确认值按文档执行，暂定值不当作最终平衡结论。
- 不修改游戏原版程序集，不把原版属性换成另一套并行体系。
- 玩家用空间、能源或维护换收益，不自动视为漏洞；是否调整看已确认设计和实际证据。

# 2. 建筑系统

建筑系统完整规则见[[2. 建筑系统设计]]；电力独立版已接入损耗结算，游戏验收未执行。本节只保留建筑系统的设计意图与机制骨架。

## 2.1 工作温度范围

**问题：** 原版建筑的温度要求只有过热温度，实际游戏中几乎不会受建筑材料影响，无论什么材料都维持在过热温度以下，建筑材料的选择缺乏思考性。

**思路：** 借鉴小动物系统的存活范围／舒适范围影响产量，给工作建筑增加两个温度范围，迫使玩家进行材料选择；同时避免「必须性」，不做成只能选一种材料的多维选择。

**机制骨架：**

- 温度对象是**建筑本体温度**，不增加独立的内部工艺温度；不同建筑有不同工作温区。
- 建筑最低工作温度 $T_{work,min}$ 由建筑类型决定，不随配方或建材改变；最高工作温度 $T_{work,max}$ 等于主建造材料决定的过热阈值 $T_{overheat}$。
- 配方只定义最佳温区 $[T_{best,min}, T_{best,max}]$，与建材无关；配方最佳下限不得低于建筑下限，高侧可以被材料上限截断甚至完全不可达。
- 未开启强制运行时：低于建筑下限进入等待／预热；在建筑可工作温区内按配方最佳区以温度效率 $\eta_T$ 影响工作时间；超过建筑上限进入高温保护，停止生产与内置加热，且不提供耐热保护。
- 温度只改变生产进度推进速度，不重置已有进度；停机保留批次、原料与进度，恢复后继续，不重新投料。

其中过热阈值与材料挂钩，公式与材料对照见 [[2. 建筑系统设计#2.1.5 过热阈值与主建造材料]]。

## 2.2 预热系统

部分建筑（例如金属精炼器）的工艺温度远高于环境温度，仅靠环境无法达到，因此需要预热系统把电力转化为建筑自身的热量。这是热量而不是固定温升，实际温升受建筑材料热容影响。

- 参考空间加热器／液体加热器：预热阶段的用电全部用于加热，不推进生产；生产用电另计。
- 预热与补热独立于生产许可，不受自动化输入控制；没有有效批次时不加热，预热不需要复制人。
- 建筑提供**默认模式**与**控制模式**：默认模式预热到启动目标后可在整个建筑可工作温区内生产；控制模式只在建筑范围与配方最佳区的交集内生产，并可在生产中补热。
- 两种模式的实际启动目标都取原目标与建筑上限的较小值；加热与生产启动判断使用同一个实际目标。
- 独立的**强制运行**开关，用于在特殊温度下继续生产；它只解除温区限制，不解除材料、供电、自动化许可与建筑完好条件，且越界仍受温度效率与过热损伤影响。

## 2.3 个性化工作温区与生产排程

不同配方有各自的最佳温区：低熔点材料适合较低工艺温度，高熔点材料需要更高工艺温度，切换配方可能需要重新预热或降温。玩家会倾向连续安排温区相近的配方，从而把**生产排程变成热管理的一部分**。

为避免配方轮换造成频繁调温，订单按玩家添加顺序执行，同一配方可在不同位置重复添加；材料齐备后先锁定当前批次及其温区，再调温与生产，其他订单的到料不抢占当前批次。

## 2.4 硬度系统革新

原版硬度主要用于挖矿，参与度低。把硬度作为**明显机械负载建筑**的考虑项（生活与娱乐建筑暂不纳入）：

- 每栋适用建筑有最低要求硬度，建筑实际硬度取主建造材料，辅料不参与。
- 硬度达标不产生机械磨损，其他伤害仍生效；硬度不足仍可生产，但按实际生产时间缓慢损伤。
- 磨损只在实际生产时累计；预热、待机、温度暂停与维修不累计。损坏复用原版过热画面，但原因单独显示为「机械磨损／机械损坏」。
- 维修触发、耗材与过程沿用原版，不增加新门槛；只有机械损坏时维修不重置温度。

## 2.5 建筑类别

建筑按「是否需要工作温区」分类，并按配方生产、连续转换、热管理、发电、物流等类别确定是否接入、接入哪条规则。分类框架、原版判定依据与完整名单见 [[2. 建筑系统设计#2.5 建筑分类与温区适用范围]]。分类只用于开发判断，不在游戏内展示给玩家。

# 3. 电力系统

原版电力只有功率一个变量，缺少线路规划与线材选择的空间。本系统增加**线路耗散**：损耗的主导因素随负载改变——低负载时以线材基础损耗为主，高负载时长线路的指数惩罚更易成为主导。

理想体验：

- 前期：随便接，损耗很小。
- 中期：工业区变大，开始感受到浪费。
- 后期：主动分区、升级主干线、优化高功率设备布局。

设计要点：

- 不引入电压、电流或逐段分流模拟；逐用电对象计算供电端到接收端的**最短有效线路长度**，结合实时功率计算损耗，绕路计入长度，多条路线取最短。
- 变压器是分割点，两端独立结算；电池类建筑区分充电与放电，分别记账。
- 导线类型决定容量参数，建造材料决定电导率；混合线材按分段累计，长度惩罚对整条路径统一计算一次。
- 每个电网把各接收对象的损耗相加，作为该电网「虚拟耗电设备」的真实支出，但不计入本电网 `wattsUsed`。

完整规则、损耗函数与未定项见 [[3. 电力系统设计]]。

# 4. 房间系统

原版房间加成偏少，使用中缺少用途。房间系统改造的出发点是让房间等级与装饰度、温度一起成为可经营的目标。

- 房间分为 T1 基础房间、T2 中级房间、T3 高级房间；低等级房间保持现状以维持开局难度。
- T2 新增与改造的房间里增加新加成（例如医院、淋浴间、人造公园）；T3 房间普遍增加**最低装饰度**要求，并给部分房间增加温度要求。
- 新增工业区、医疗中心、舞厅、街机厅、海滨乐园、展览馆、风洞训练室、水疗室、茶歇室、任务控制室、地质研究室、航天发射场、星际货运站、数据机房等房间。
- 装饰度：为部分材料增加或修改装饰度加成；房间装饰度按房间内格子的平均装饰度判定，复制人装饰感知值与计算方法不改。
- 房间温度采用房间平均温度。

完整房间清单、构成要求与加成数值见 [[4. 房间系统设计]]。
