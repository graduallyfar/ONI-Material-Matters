# ONI-Reform · Material Overhaul（材料革新）

让**建造材料**真正参与建筑运算的《缺氧》模组：材料的热容、导热、熔点与硬度决定建筑能在多高的温度下工作、要花多少电把建筑加热到工艺温度、以及生产时会磨损到什么程度。

**版本 0.2.2** · 测试于游戏 build `744825` · 只需游戏自带的 0Harmony，无其他前置

> [!WARNING]
> 温控、订单与磨损在代码中已覆盖 **29 栋工业建筑**：原六栋（金属精炼器、岩石粉碎机、玻璃熔炉、分子熔炉、化学精炼厂、窑炉）已经过游戏内运行，第三批 23 栋（批次加工、连续转换、燃料发电、油井、矿石洗涤器）**已完成源码级回归，2026-10-17 已部署到本地 mod 目录（DLL 0.2.2.0），尚未在游戏内验收**。材料过热百分比、深渊晶石矿物原料分类与精炼金属建材扩展适用于全局。数值仍属初值，未上传 Steam 创意工坊。

## 独立验证版本

同一工程提供三种构建，版本号仍为0.2.2：

| 模式 | 功能 |
| --- | --- |
| Industrial | 仅工业温控、加热、订单、磨损与材料改造；电力输配电保持原版 |
| Power | 仅电力基础功能与当前电网电线数；工业及材料机制保持原版，线路损耗尚未启用 |
| Combined | 工业与电力整合验证 |

验证包分别位于 `_dist/validation/<模式>/MaterialOverhaul/`，另有同名ZIP。三种包使用同一个Mod ID，切换时替换安装并重启游戏，每次只启用一份，分别使用专门测试存档。详细边界与验证记录见[系统隔离验证记录](docs/开发计划/系统隔离验证记录.md)。下列工业功能适用于Industrial和Combined。

## 它做了什么

- **工作温区**：建筑最低工作温度由建筑类型决定；最高工作温度 = 过热阈值 = **主建造材料熔点 × 0.75 × 材料过热倍率**（按 K 计算）。配方另有自己的最佳温区，切换配方不改变建筑上下限。窑炉、铀素离心机、乙醇蒸馏器、藻类蒸馏器与氧石精炼炉保留原版过热豁免，材料上限只限制工作。
- **材料修正**：原有正向过热加成统一为 **+60%**，深渊晶石无加成；深渊晶石可用于矿物原料建筑，接受金属矿石的建材槽位也可选精炼金属。过热扣血沿用原版速率。
- **温度效率**：最佳温区内 100%，偏离最佳区按指数衰减到该建筑的低／高侧底值。批次建筑温度不达标只暂停当前批次并保留原料与进度；连续转换与发电则按同一效率同比缩放原料、全部产物、燃料、排放与发电量。
- **预热与补热**：有内置加热的建筑提供 **20–4000 W** 滑条（默认 1200 W，每栋独立保存），预热、补热和强制加热共用；生产用电另计。
- **强制运行**：独立开关，解除温区停机限制，但仍需要材料、供电、复制人操作和完好的建筑；发生过热损坏后会停止内置加热，完全维修才恢复。
- **订单排程**：按玩家添加顺序执行，同一配方可重复添加；材料齐备后先锁定批次与温区，再调温生产。
- **硬度与磨损**：主建造材料硬度不足时按实际生产时间产生磨损并扣生命值；维修沿用原版，只有机械损坏时维修不重置温度。连续设备按真实转换秒数计时，并行转换不重复计。
- **自动化**：输入端口「允许生产」（未接线默认放行，只控制是否生产，不影响预热）；输出端口「温度区间」，接线即进入控制模式，处于最佳温区时输出绿色。

## 已接入建筑

**原六栋（已游戏内运行过）：** 金属精炼器、岩石粉碎机、玻璃熔炉、分子熔炉、化学精炼厂、窑炉。

**第三批 23 栋（已部署，待游戏验收）：** 漂白石料斗、钻石压机、铀素离心机、硫化器、胶合板压机、泥浆分离器、爆破弹组装机；原油精炼器、聚合物压塑器、乙醇蒸馏器、肥料合成器、藻类蒸馏器、氧石精炼炉、净水器、脱盐器；煤炭／泥炭／氢气／天然气／石油／木材发电机；油井、矿石洗涤器。

参考数值：金属精炼器下限 80 ℃（炼铝最佳区 450–650 ℃，内置加热 1200 W）、岩石粉碎机 −20 ℃／240 W／无内置加热、窑炉 −20 ℃／无电。建筑上限由建材决定：例如炼铝 450–650 ℃ 在黑曜石、陶瓷、火成岩上完整可达，砂岩只能覆盖一部分。

完整数值见 [建筑系统设计](<docs/Mod玩法设计和修改/2. 建筑系统设计.md>)：§2.6 首批三栋、§2.7 第二批三栋、§2.8 第三批 23 栋。

## 安装

把下面这些文件放进 Klei 数据目录的本地 Mod 文件夹：

```text
%USERPROFILE%\Documents\Klei\OxygenNotIncluded\mods\local\MaterialOverhaul\
├─ MaterialOverhaul.dll
├─ mod.yaml
├─ mod_info.yaml
├─ build_profile.json
└─ strings\zh.po
```

文档目录被重定向到其它盘符时以实际位置为准。放好后启动游戏，在「模组」菜单勾选启用并重启。

- 本地化必须叫 `strings\zh.po`，改名会导致界面显示 `MISSING.STRINGS.*`。
- `mod.yaml` / `mod_info.yaml` 不能带 BOM，否则会报属性名解析警告。
- 旧存档：v0.1.0 起金属精炼器输出端口改到 `(1,3)`，旧档需要在新位置补接线。

## 从源码构建

需要 .NET SDK、PowerShell 7（Codex终端已提供）和本机安装的《缺氧》。在工作区根目录执行：

```powershell
copy MaterialOverhaul\local.props.example MaterialOverhaul\local.props   # 填入自己的 GameDir
dotnet build MaterialOverhaul\MaterialOverhaul.csproj -c Release
dotnet run --project tests\MaterialOverhaul.Tests\MaterialOverhaul.Tests.csproj -c Release
pwsh -NoProfile -ExecutionPolicy Bypass -File MaterialOverhaul\tools\build-profiles.ps1
pwsh -NoProfile -ExecutionPolicy Bypass -File MaterialOverhaul\tools\deploy.ps1 -Profile Power
```

直接dotnet构建默认Combined，产物在 `_build/profiles/Combined/`。`build-profiles.ps1`生成并检查三种包；`deploy.ps1`必须明确选择Industrial、Power或Combined，校验后只写 `mods\local\MaterialOverhaul`，切换前备份旧文件，不触碰订阅目录与存档。构建时的 `MSB3277` 属预期警告。
