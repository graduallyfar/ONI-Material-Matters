# ONI-Reform · Material Overhaul（材料革新）

> 让**建造材料**真正参与建筑与系统运算的《缺氧》模组。

本 Mod 不增加新材料，也不是单纯重平衡现有数值，而是改变「材料属性如何参与建筑、环境和系统运算」的方式：材料的热容、导热、熔点与硬度会决定建筑能在什么温度区间工作、要花多少电把建筑本体加热到工艺温度、以及生产时会磨损到什么程度。目标是让原本差异不明显的建材选择，变成真正的工程选择。

**当前版本：`0.2.1`　|　生效建筑：金属精炼器、岩石粉碎机、玻璃熔炉（仅此三栋）　|　游戏内完整验收：未执行**

## 2. 已实现机制

### 2.1 建筑工作温区与温度效率

温度对象是**建筑本体**，不增加独立的内部工艺温度。

- **建筑最低工作温度 `L`** 由建筑类型决定，不随配方或建材改变。
- **建筑最高工作温度与过热阈值是同一个值**：`U = 过热阈值 = 0.75 × 主建造材料熔点`，公式按开尔文计算后再换算显示单位。建材因此直接决定建筑能烧到多高。
- **配方只定义自己的最佳温区 `[B₁, B₂]`**，与建材无关。切换配方不改变建筑的工作上下限。

两种普通模式：

| 模式 | 选择方式 | 可生产温度区间 |
| --- | --- | --- |
| 默认模式 | 温区输出端口**未接线** | `[L, U]` |
| 控制模式 | 温区输出端口**已接线** | `[B₁, min(B₂, U)]` |

温度效率 `η_T`：

```text
η_T(T) = 1                                  B₁ ≤ T ≤ B₂
       = εL ^ ((B₁ − T) / (B₁ − L))         L ≤ T < B₁
       = εH ^ ((T − B₂) / (U − B₂))         B₂ < T ≤ U
       = εL（T < L）／εH（T > U）            仅强制运行可达
```

- 效率只乘**生产进度速度**，不改变投入、收率与产物质量；一批 40 s 的配方在 η=0.3 时需要 133.33 s。
- 效率只由配方温度关系与建筑范围决定，不随建材改变；建材只通过 `U` 改变高温段的终点。最佳区内即使超过 `U`（强制运行）也仍是 100%，实际过热风险单独显示。
- `U ≤ B₂` 时不存在普通模式高温段；强制超过 `B₂` 直接取该建筑的高侧底值。

温度不满足时**只暂停当前批次**：保留已投原料与生产进度，释放复制人，停止生产用电与生产自热；温度恢复后继续，不重新投料、不重置磨损。

### 2.2 预热、补热与加热功率

- 有内置加热的建筑（金属精炼器、玻璃熔炉）提供 **20–4000 W、1 W 精度、默认 1200 W** 的加热滑条，位置在建筑配方卡下方，**每栋建筑独立保存**。
- **预热、补热与强制持续加热共用这条滑条**，取代旧版固定补热额外 200 W；生产用电另计。
- 注热倍率 `M = 100`（初值）：`注热功率(kW) = 滑条(W) / 1000 × 100`。默认 1200 W 对应 120 kW 注热。**该倍率与保温可达性尚未进行游戏平衡验收。**
- 启动线沿用比例 0.1 的公式，实际目标取原值与建筑上限的较小值：

```text
默认模式原目标 T_start = L + 0.1 × (B₁ − L)
控制模式原目标 T_start = B₁ + 0.1 × (B₂ − B₁)
实际目标 = min(原目标, U)
```

- 控制模式生产时，温度低于补热线即边生产边补热；加热与生产启动判断共用同一个实际目标。
- 没有有效批次不加热；断电、手动禁用、建筑损坏停机都会停止加热。断电时保留加热需求但实际消费为 0。
- **岩石粉碎机没有内置加热**，只能靠环境升温或生产自热；温度不满足时显示等待升温，不显示正在预热。

### 2.3 强制运行

- 每个生效建筑有独立的**强制运行**开关（建筑面板）。
- 覆盖默认模式与控制模式的温区停机限制：未达 `L` 或超过 `U` 都能继续生产。未达 `L` 时取该建筑的低侧底值，超过 `U` 时取高侧底值；若超过 `U` 但仍落在配方最佳区内，效率仍是 100%。
- **只解除温区限制**，不解除材料、供电、自动化生产许可、复制人操作与建筑完好条件；生命值耗尽仍然停机。
- 首次实际过热扣血后停止内置加热并撤掉加热需求，**完全维修**后解除。切换强制开关、换配方、降温和读档都不会解除该保护。
- 岩石粉碎机没有内置加热功率，强制运行不会凭空产生加热器。
- 关闭开关后按当时的输出端口接线重新判断基础模式，并保留当前批次。

### 2.4 订单排程

- 订单按**玩家依次添加的顺序**执行，同一配方可以在不同位置重复添加；不恢复原版按配方列表轮转的调度。
- 有限订单连续执行，缺料时保留剩余数量并向后问询；无限订单完成设定的一轮批次（默认 1 批）后让出，之后继续参与轮换。全部缺料时等待材料，不空转。
- **材料齐备后先锁定当前批次及其温区，再进行调温与生产**；其他订单到料不抢占当前批次，温度暂停不触发配方切换。
- 暂停与取消分别处理，取消不会误触发完成。有限订单数量上限沿用原版 99。

### 2.5 硬度、磨损与维修

- 适用建筑有一个**要求硬度**（首发三栋均为 25，取原版 `Element.hardness` 分级）。
- 建筑实际硬度由**主建造材料**决定，辅料不参与。达到或超过要求时不产生机械磨损，其他伤害（过热等）不受影响；硬度差只决定有无磨损，不引入差值倍率。
- 硬度不足时按**实际生产时间**累计磨损：预热、待机、温度暂停、等工人、维修与损坏期间都不累计，生产中补热也不增加第二份磨损。累计磨损按建筑独立转换率扣减生命值。

| 建筑 | 磨损累计 | HP / 生产秒 |
| --- | --- | --- |
| 金属精炼器 | 1 单位／实际生产秒 | 0.05 |
| 岩石粉碎机 | 1 单位／实际生产秒 | 0.02 |
| 玻璃熔炉 | 1 单位／实际生产秒 | 0.025 |

- 暂停、换单与读档不会清除已累计的磨损与浮点伤害余额。
- 维修触发、材料成本与流程**沿用原版**，不新增维修门槛。只有机械损坏时维修不重置温度；包含过热损坏时按原版过热维修时机重置（293.15 K／20 ℃）。
- 损坏原因分开显示：机械磨损、过热、以及两者同时存在；强制运行发生过热损坏时即使没有实际机械磨损也显示两种原因，但不会额外制造机械扣血。

### 2.6 自动化与供电

| 端口 | 作用 |
| --- | --- |
| 输入「允许生产」 | 只控制是否允许生产，不控制选定配方、预热与补热；未接线默认放行 |
| 输出「温度区间」 | 接线时进入**控制模式**，未接线为**默认模式**；有锁定配方且处于最佳温区为绿，其余为红 |

- 输出只有绿／红两种信号，没有第三种空信号；**绿色只代表温度条件满足，不代表正在生产**；温区整体未配置时不发绿。
- 输入红信号停产时仍保留有效批次的预热与补热。
- 内置加热用电已接入电网：需求与实际消费分开记账，断电时保留需求但注热为 0；禁用、损坏或无有效批次时不保留加热需求。

### 2.7 界面与文案

- 建筑效果区显示本栋**工作温度**及上限来源，配方详情显示该配方的**最佳温区**；配方名与原版描述保持原样，不追加温区后缀。
- 状态栏显示运行状态（预热、补热、生产中、低效生产中、降温中、等待升温、温度受限等）、当前模式（默认／控制／强制）、风险与损坏原因；模式项与运行项不在建筑上方绘制图标。
- 配置卡保留原版「当前生产／下一生产」与配方操作，不额外增加订单侧屏。
- 中文本地化共 80 条，按本机原版中文校对用词。

### 3.3 岩石粉碎机与玻璃熔炉

- **岩石粉碎机**：全部 26 个配方候选（14 条固定配方／集合 + 12 条动态金属输入）**共用最佳温区 15–60 ℃**、基准时间 40 s、生产用电 240 W；没有内置加热与加热滑条。动态金属输入输出为「金属 50 kg + 砂 50 kg」。
- **玻璃熔炉**：`砂 100 kg → 熔融玻璃 25 kg`，基准时间 40 s，生产用电 1200 W，**最佳温区 900–1200 ℃**；保留原版 25% 质量收率与熔融玻璃 2215 K 的输出温度。

### 3.4 建材决定可达性

由于 `U = 0.75 × 主建造材料熔点(K)`，同一配方在不同建材下的可达性不同。例如炼铝（450–650 ℃）：

| 主建造材料 | 上限 `U` | 控制模式最佳区 |
| --- | --- | --- |
| 黑曜石 | 1976.85 ℃ | 完整可达 |
| 陶瓷 | 1319.1 ℃ | 完整可达 |
| 火成岩 | 989.1 ℃ | 完整可达 |
| 砂岩 | 626.85 ℃ | 部分可达 |
| 花岗岩 | 433.35 ℃ | 不可达（低于最佳下限） |

上限低于最佳下限时，普通模式只能在建筑上限处受限运行，越界生产需要开启强制运行并承担过热风险。温度效率曲线图见 [首发三建筑效率曲线](<Mod玩法设计和修改/assets/首发三建筑效率曲线.png>)。

## 4. 安装

**前置：** 《缺氧》build ≥ `744825`。游戏自带 `0Harmony` 2.4.2.0，无需额外安装依赖；本 Mod 不附带任何游戏原版程序集。

本 Mod 目前**未上传 Steam 创意工坊**，正式版本发布前请先按第 5 节自行构建，或使用已构建好的文件手动安装。

手动安装：把下列文件放进 Klei 数据目录下的本地 Mod 目录。

```text
<Klei 数据目录>\mods\local\MaterialOverhaul\
├─ MaterialOverhaul.dll
├─ mod.yaml
├─ mod_info.yaml
└─ strings\
   └─ zh.po
```

Windows 上的默认位置是 `%USERPROFILE%\Documents\Klei\OxygenNotIncluded\mods\local`；如果系统文档目录被重定向到其它盘符，以实际位置为准（`deploy.ps1` 也支持 `-ModsDir` 显式指定）。安装后在游戏内「模组」菜单勾选启用并重启游戏。

注意事项：

- 本地化文件必须叫 `strings\zh.po`，原版只扫描 Mod 目录下的 `strings\*.po`；改成 `translations` 或 `.json` 会导致界面显示 `MISSING.STRINGS.*`。
- `mod.yaml` / `mod_info.yaml` 必须**不带 BOM**，否则原版会报属性名解析警告。
- 不要拷贝 `MaterialOverhaul.deps.json`，游戏加载不需要它。
- 旧存档注意事项：v0.1.0 起金属精炼器的输出端口坐标改为 `(1,3)`（输入仍为 `(0,3)`），旧存档需要在新输出位置补接线。

## 5. 从源码构建

**需要：** 任意较新的 .NET SDK（仅作构建工具，目标框架由游戏程序集核实为 `netstandard2.1`，不由本机 SDK 推断）＋ 本地安装的《缺氧》。

```powershell
# 1. 复制并修改本地游戏路径配置（local.props 已被 .gitignore 忽略）
copy MaterialOverhaul\local.props.example MaterialOverhaul\local.props
#    编辑 local.props，把 GameDir 指向缺氧安装根目录

# 2. 构建（产物在 _build\）
dotnet build MaterialOverhaul\MaterialOverhaul.csproj -c Release

# 3. 运行判断层与接入层源码级测试
dotnet run --project tests\MaterialOverhaul.Tests\MaterialOverhaul.Tests.csproj -c Release

# 4. 构建并部署到本机 mods\local\MaterialOverhaul
powershell -NoProfile -ExecutionPolicy Bypass -File MaterialOverhaul\tools\deploy.ps1
```

说明：

- `deploy.ps1` 只写入 `<Klei 数据目录>\mods\local\MaterialOverhaul`，不触碰 `mods\Steam` 与任何存档；可用 `-ModsDir` 显式指定目录，用 `-SkipBuild` 跳过构建。
- 脚本会拒绝把 `Assembly-CSharp*.dll` 等原版程序集复制进部署目录。
- 构建时的 `MSB3277`（游戏程序集与 netstandard2.1 引用程序集版本冲突）属预期，已在工程内降级为消息。
- `deploy.ps1` 保存为 UTF-8 **带 BOM**，因为 Windows PowerShell 5.1 读取不带 BOM 的脚本会按 ANSI 解析中文而报语法错误。

## 6. 测试

`tests\MaterialOverhaul.Tests\` 是一个不依赖游戏运行时的控制台测试工程，当前 **1405 项断言全部通过**，覆盖：

- 温区判断、效率分段与边界（含 `U ≤ L`、单点交集、窄交集等退化情况）
- 启动线、补热线与高温恢复回差
- 加热意图、功率换算与供电需求
- 有序订单队列、数量记账与身份一致性
- 硬度磨损累计、伤害转换与损坏原因判定
- 配方登记源码与游戏替身、状态项文本树与图标开关回归

判断层（`Core/`、`Zones/`、`Heating/`、`Hardness/`、`Orders/`）不引用任何游戏类型，因此可以脱离游戏单独检查；但这些断言**只是源码级回归，不能代替游戏内验收**。

## 10. 已知限制与未验证项

- **只有三栋建筑生效**，其余建筑行为完全等同原版；未配置温区的配方也按原版运行。
- 全部数值（建筑下限、配方最佳区、效率底值、注热倍率、磨损转换率）目前是**初值或暂定值**，不代表最终平衡。
- **游戏内验收尚未完成**：界面悬停与图标、实际升降温速度、断电与自动化行为、读档一致性、维修与过热损坏的完整表现都还没有在游戏里逐项跑完。
- 注热倍率 `M = 100` 在真实保温结构下的可达性需要专用存档实测；数学上的预热量只是无散热下限。
- 依赖 DLC 的配方在未启用对应 DLC 时正常跳过；未知 Mod 新增的配方不会被自动套用温区数值。
- 部分数值边界（`U < B₁`、`U = B₁`、`U ≤ L` 等退化组合）只有源码级回归，尚无游戏内记录。
